# Pi 通用 Agent 项目需求说明

基于 Pi Coding Agent 二次开发的完整功能规划与验收基线

版本 1.0  |  日期 2026 年 11 月 28 日

文档用途：指导个人学习型通用 Agent 项目的范围定义、模块设计、分阶段实现与验收。

## 文档摘要

本项目以 Pi Coding Agent / Pi Mono 为基础，构建一个可扩展、可观察、可控且能够处理多步骤任务的通用 Agent。项目既复用 Pi 的模型适配、Agent 执行循环、会话和扩展机制，也将规划、工具治理、记忆、检索、后台任务、评估和安全作为需要系统理解与完善的工程能力。首要目标是形成一套可运行、可逐步替换、可回归验证的学习项目，而不是只增加一组提示词或工具。

## 阅读与需求标识

需求优先级：P0 为基础运行和安全闭环；P1 为完整个人通用 Agent 的主要增强能力；P2 为高级自治、协作和多模态扩展。优先级表示建议实施顺序，不代表可以忽略的永久范围。需求编号可用于后续任务拆分和验收追踪。

| 字段 | 说明 |
| --- | --- |
| 需求编号 | 唯一标识，便于拆分、实现、测试与追踪。 |
| 优先级 | P0 / P1 / P2。 |
| 验收方式 | 可观察、可重复验证的完成条件。 |
| 范围假设 | Pi 指公开的 Pi Coding Agent / Pi Mono；具体仓库版本和改动策略在开工时锁定。 |

## 1 项目概述与目标

### 1.1 项目背景

Pi 提供了轻量、可扩展的 Agent harness，适合作为学习和二次开发的基础。项目将它扩展为通用任务 Agent：用户可通过自然语言提出目标，Agent 能理解目标、形成计划、使用经授权的工具、根据执行结果调整步骤，并最终交付可核查的结果。

### 1.2 项目目标

- 理解并掌握从模型请求、Agent 循环、工具执行到状态持久化的完整运行链路。
- 构建可处理信息检索、文件分析、内容生成、代码执行和外部系统操作的通用能力。
- 让任务执行过程可观察、可中断、可恢复、可评估。
- 为有副作用的动作建立权限、预览、审批、审计和失败恢复闭环。
- 支持通过工具、Skills、MCP、扩展和工作流逐步增加能力。
- 保留 Pi 的可组合和轻量特点，避免将业务逻辑全部耦合进运行时核心。
### 1.3 成功定义

- 核心场景能够端到端完成，并满足各场景验收条件。
- 运行轨迹足以解释 Agent 做了哪些模型调用、工具调用和状态转换。
- 任务失败或中断时，能说明已完成部分，并在支持的场景中安全恢复。
- 权限不足、审批拒绝、预算耗尽或安全边界触发时，系统能够停止并留下清晰状态。
- 关键变更拥有可重复的评估用例，升级后可发现质量、安全或成本退化。
## 2 产品范围与边界

### 2.1 本项目范围

- 以个人学习和本地/自托管使用为主要目标。
- 首期交互以 CLI/TUI 为主，架构预留 Web/API 和通知入口。
- 首期提供本地文件、网页检索、代码/命令执行及可选知识库能力。
- 支持单 Agent 完整闭环，并将多 Agent 设计为后续可选能力。
- 采用模块化方式组织模型、工具、状态、记忆、审批、评估与界面。
### 2.2 暂不作为首期前提

- 面向多租户企业的完整商业 SaaS、计费和组织管理。
- 对所有工具和外部动作无差别自动授权。
- 保证模型对所有开放式任务都正确完成。
- 依赖复杂多 Agent 才能处理基础任务。
### 2.3 核心使用场景

| 场景 | 输入示例 | 预期产出 |
| --- | --- | --- |
| 研究与问答 | 比较某技术方案并提供来源 | 结构化结论、来源引用、待确认事项 |
| 文件分析 | 总结目录中的资料并提取差异 | 摘要、比较表、来源文件定位 |
| 内容与交付物 | 基于资料生成报告或计划 | 文档、表格或结构化内容及变更说明 |
| 代码与命令 | 分析项目、修改代码、运行检查 | 变更差异、执行结果、剩余风险 |
| 外部系统操作 | 创建日程、发送消息、更新任务 | 执行预览、审批记录、操作回执 |
| 长期任务 | 分阶段完成研究并等待用户反馈 | 持久任务状态、进度更新、可恢复执行 |

## 3 用户与使用场景

### 3.1 主要用户

- 项目所有者：配置模型、工具、权限和运行环境。
- 日常使用者：提出目标、补充信息、审批动作并查看结果。
- 开发/学习者：查看轨迹、调整模块、运行评估并比较实现方案。
### 3.2 典型任务生命周期

1. 用户提交目标和可选约束。
1. Agent 解析目标，识别缺失信息、权限和风险。
1. 必要时向用户澄清；复杂任务展示计划。
1. Agent 按计划调用工具并检查环境反馈。
1. 对高影响操作展示具体动作并等待审批。
1. Agent 根据结果调整步骤，处理失败或部分完成。
1. 系统保存最终结果、运行轨迹、费用和可恢复状态。
## 4 总体架构与设计原则

### 4.1 逻辑模块

| 模块 | 职责 |
| --- | --- |
| Pi 适配层 | 接入 Pi 模型、Agent、会话、扩展和工具运行能力；封装版本差异。 |
| Agent Runtime | 运行循环、事件流、状态机、取消、超时、预算和恢复。 |
| Task Planner | 意图解析、约束提取、任务拆解、步骤依赖和完成判定。 |
| Model Provider | 模型注册、能力描述、路由、回退、超时和成本计量。 |
| Tool Registry | 工具定义、参数校验、权限、风险分级、执行和审计。 |
| State & Session | 会话消息、任务步骤、审批状态、运行事件和检查点持久化。 |
| Knowledge & Memory | 文件处理、检索、引用、用户偏好和项目记忆。 |
| Policy & Approval | 身份权限、动作策略、审批生命周期和安全停止。 |
| Observability & Eval | 追踪、日志、成本、指标、数据集、评分和回归。 |
| Interfaces & Extensions | CLI/TUI、API、通知、Skills、MCP、插件和工作流。 |

### 4.2 设计原则

- 先理解并复用 Pi 已有能力，形成差距清单后再实现扩展。
- 核心运行时与具体工具、领域流程、界面解耦。
- 对所有外部动作采用最小权限和可追溯执行。
- Agent 计划不是事实；关键步骤以工具返回和真实状态为依据。
- 可恢复任务必须把状态写入持久层，而不是依赖内存上下文。
- 工具边界和策略代码承担安全责任，提示词只作为补充。
- 功能优先级服从可验证性、学习价值和风险控制。
## 5 功能需求

以下功能需求形成项目完整需求池。具体是否由 Pi 原生提供、通过扩展接入或由项目自行实现，应在技术设计阶段逐项盘点，并记录版本和验收证据。

### 5.1 模型与推理运行时

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| MOD-001<br>P0 | 系统应支持配置并选择至少一个模型提供方及模型。 | 更改配置后可运行同一用例并确认模型信息记录正确。 |
| MOD-002<br>P1 | 系统应允许按任务类型、能力、成本或延迟路由模型。 | 路由规则命中可通过运行轨迹验证。 |
| MOD-003<br>P1 | 系统应支持模型失败后的回退策略和可配置重试。 | 模拟超时后按策略回退，且不重复执行副作用工具。 |
| MOD-004<br>P1 | 系统应记录模型请求状态、耗时、用量和错误。 | 运行详情包含每次模型调用的状态和可用用量。 |
| MOD-005<br>P2 | 系统应支持本地模型、自定义端点和能力声明。 | 可连接本地端点并明确标记其能力限制。 |
| MOD-006<br>P0 | Agent Runtime 应支持流式响应、工具调用循环和用户取消。 | 流式输出期间取消后不再启动后续步骤。 |
| MOD-007<br>P0 | 每次运行应有唯一标识、状态、开始/结束时间和终止原因。 | 运行记录可按 ID 查询，状态转换合法。 |
| MOD-008<br>P0 | 系统应限制最大执行时长、模型轮数、工具调用数和预算。 | 达到任一上限后停止并返回明确原因。 |

### 5.2 任务理解与规划

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| PLN-001<br>P0 | 系统应提取用户目标、交付物、范围、格式及显式约束。 | 测试输入中的约束均出现在任务结构或计划中。 |
| PLN-002<br>P0 | 信息不足且影响执行时，系统应提出最少必要澄清问题。 | 澄清前不执行依赖缺失信息的高影响动作。 |
| PLN-003<br>P1 | 系统应将复杂任务拆分为有依赖关系的步骤。 | 计划包含可执行步骤、依赖和完成条件。 |
| PLN-004<br>P1 | 用户应能查看、修改或确认计划。 | 计划修改后执行使用更新版本。 |
| PLN-005<br>P1 | 运行中可依据工具结果和新约束更新计划。 | 轨迹记录计划版本及变更原因。 |
| PLN-006<br>P0 | 系统应定义任务完成条件、停止条件和部分完成状态。 | 未满足交付条件时不得标记为完整成功。 |
| PLN-007<br>P1 | 系统应报告进度、阻塞点、已完成步骤和待执行步骤。 | 运行中及结束时可查询状态摘要。 |

### 5.3 工具注册与执行

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| TLS-001<br>P0 | 工具应声明名称、用途、参数 schema、权限和风险等级。 | 注册时缺少必要元数据的工具不能启用。 |
| TLS-002<br>P0 | 调用工具前应校验参数类型、必填字段和业务约束。 | 非法参数不进入工具执行函数。 |
| TLS-003<br>P0 | 系统应区分只读、可撤销写入和高影响操作。 | 每个工具调用轨迹显示风险类别。 |
| TLS-004<br>P0 | 系统应限制每个 Agent 可用的工具集合。 | 未授权工具调用被拒绝并记录原因。 |
| TLS-005<br>P1 | 系统应支持工具超时、有限重试、取消和错误分类。 | 模拟错误后状态与错误类别正确。 |
| TLS-006<br>P1 | 工具输出应限制大小并支持截断或结构化摘要。 | 超限输出不会导致运行失控，且记录截断信息。 |
| TLS-007<br>P1 | 系统应支持工具版本、健康状态和停用。 | 停用工具不再被模型调用。 |
| TLS-008<br>P1 | 系统应提供工具前后钩子以执行策略检查和结果验证。 | 钩子失败时按 fail-closed 规则阻止危险操作。 |
| TLS-009<br>P1 | 副作用工具应支持幂等键或重复执行保护。 | 重复请求不产生重复外部动作。 |

| --- | --- | --- |

| INT-002<br>P1 | 系统应具备网页搜索、打开、内容提取及来源记录能力。 | 答案中的引用能定位到实际检索结果。 |
| INT-003<br>P1 | 系统应支持受控代码或命令执行。 | 执行记录包含命令、工作目录、退出码和输出。 |
| INT-004<br>P1 | 系统应支持计算、JSON/CSV 处理及 HTTP/API 调用。 | 结构化输入输出经过 schema 校验。 |

| INT-006<br>P1 | 系统应支持通过扩展注册命令、工具或事件处理器。 | 扩展加载、禁用、错误隔离和版本可观察。 |
| INT-007<br>P2 | 系统应支持邮件、日历、任务系统等外部连接器。 | 授权、读写范围和审批策略可单独配置。 |

### 5.5 文件、知识和研究

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| KNO-001<br>P1 | 系统应解析授权范围内的常见文本、代码和结构化文件。 | 对受支持文件产生可核查的提取结果。 |
| KNO-002<br>P1 | 系统应支持多文档问答、摘要、比较和信息提取。 | 输出可追溯到文件名及必要的位置。 |
| KNO-003<br>P1 | 知识库应支持导入、索引、更新、删除和重建索引。 | 索引状态及失败原因可查询。 |
| KNO-004<br>P1 | 检索结果应携带来源、片段和可用的定位信息。 | 主要结论可映射到来源片段。 |
| KNO-005<br>P1 | 系统应区分外部事实、模型推断及未验证假设。 | 结果中明确标示证据不足或来源冲突。 |
| KNO-006<br>P2 | 研究流程应支持多轮搜索、来源比较和信息时效判断。 | 研究报告包含来源日期、观点差异和未决问题。 |
| KNO-007<br>P1 | 知识检索必须遵循来源权限和用户数据隔离。 | 无权限文档不出现在检索结果中。 |

### 5.6 会话、上下文与记忆

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| MEM-001<br>P0 | 系统应持久化会话、消息、运行关联和基本状态。 | 重启后可查询历史会话和结果。 |
| MEM-002<br>P1 | 系统应支持会话搜索、重命名、归档、导出和删除。 | 操作影响范围可验证，删除后按策略清除。 |
| MEM-003<br>P1 | 系统应在长会话中摘要上下文并保留约束、目标和状态。 | 压缩前后关键约束一致。 |
| MEM-004<br>P1 | 长期记忆应区分用户、项目和会话范围。 | 记忆检索仅返回当前授权范围数据。 |
| MEM-005<br>P1 | 用户应能查看、修改、删除或关闭记忆。 | 变更后后续运行体现最新记忆状态。 |
| MEM-006<br>P1 | 记忆应支持来源、时间、置信度、过期和冲突处理。 | 过期或冲突记忆不会被无提示地当作确定事实。 |

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| ORC-001<br>P1 | 系统应支持保存可复用任务模板或工作流。 | 模板可实例化，运行结果关联模板版本。 |
| ORC-002<br>P1 | 工作流应支持顺序、条件分支、校验和失败路径。 | 分支由可测试条件触发。 |

| MM-002<br>P2 | 系统可支持音频转写、语音输入和语音输出。 | 识别结果可查看并允许纠正。 |
| MM-003<br>P2 | 系统可支持视频关键帧分析或摘要。 | 输出标记时间戳和处理范围。 |
| MM-004<br>P2 | 媒体输入应设置格式、大小、时长和保留策略。 | 超限文件被拒绝且说明限制。 |

## 6 安全与治理需求

| 编号 / 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- |
| SEC-001<br>P0 | 系统应按最小权限原则配置用户、Agent、工具和数据源访问范围。 | 越权请求被拒绝，并在审计记录中保留原因。 |
| SEC-002<br>P0 | 只读工具与有副作用工具应使用不同策略。 | 策略测试覆盖读、写、删除和外部发送。 |
| SEC-003<br>P0 | 高影响操作执行前应展示目标、参数和预期影响，并按策略审批。 | 未审批操作不会进入执行函数。 |
| SEC-004<br>P0 | 审批应绑定具体动作与参数，动作变化后必须重新审批。 | 修改目标或参数会使原审批失效。 |
| SEC-005<br>P0 | 外部网页、文件、邮件和工具返回内容均按不可信数据处理。 | 注入测试不能覆盖系统策略或触发越权动作。 |
| SEC-006<br>P0 | 工具执行端应再次校验身份、范围、目标和参数。 | 绕过模型提示仍不能绕过工具边界校验。 |
| SEC-007<br>P1 | 代码和系统命令应尽可能在隔离环境运行。 | 沙箱限制目录、网络、资源和运行时长。 |
| SEC-008<br>P0 | 凭证应安全存储，不应进入提示词、普通日志或输出文件。 | 检查运行日志和任务产物无明文凭证。 |
| SEC-009<br>P1 | 系统应记录审批人、策略版本、工具动作及结果。 | 审计记录可按运行 ID 查询。 |
| SEC-010<br>P1 | 安全检查不可用或授权状态不确定时，高风险操作应 fail closed。 | 模拟策略服务异常后危险操作被阻止。 |
| SEC-011<br>P1 | 系统应支持敏感数据脱敏和可配置留存期限。 | 删除及过期任务符合保留策略。 |
| SEC-012<br>P1 | 支持用户撤销连接器授权并查看已授予权限。 | 撤销后新的连接器调用失败。 |

## 7 非功能需求

| 类别 | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-001 可维护性 | 模块边界清晰；模型、存储、工具和界面可替换。 | 核心模块有接口说明和依赖图。 |
| NFR-002 可观测性 | 运行轨迹覆盖计划、模型、工具、审批、状态和结果。 | 按运行 ID 可还原完整执行链。 |
| NFR-003 可靠性 | 工具失败、重试和恢复行为可预测且不会重复副作用。 | 异常注入场景满足安全预期。 |
| NFR-004 性能 | 可配置并发、超时和资源限额，避免单任务阻塞整个进程。 | 并发运行时任务相互隔离。 |
| NFR-005 成本 | 可计量模型和工具费用，支持单任务预算。 | 达到预算上限后停止并输出摘要。 |
| NFR-006 可移植性 | 优先支持目标操作系统；路径、进程和沙箱能力按平台适配。 | 安装文档覆盖目标环境。 |
| NFR-007 可测试性 | 关键模块可用模拟模型和模拟工具进行确定性测试。 | 无需外部账号即可运行核心测试集。 |
| NFR-008 隐私 | 遵循最小数据收集、可删除和权限隔离原则。 | 数据目录、日志和保留策略有说明。 |
| NFR-009 可访问性 | 终端输出保持可读、可键盘操作，错误信息可理解。 | 主流程可仅用键盘操作。 |
| NFR-010 可升级性 | 固定 Pi 依赖版本并记录兼容性；升级可执行回归。 | 升级记录和回归结果可追溯。 |

## 8 数据与状态模型

建议至少定义以下核心实体；字段和存储技术可在设计阶段确定。

| 实体 | 关键内容 |
| --- | --- |
| AgentConfig | 名称、指令版本、模型策略、工具集、权限策略、预算和启用状态。 |
| Session | 用户/项目范围、消息序列、创建时间、归档和记忆设置。 |
| TaskRun | 目标、计划版本、运行状态、预算、当前步骤、开始/结束时间及结果。 |
| RunEvent | 模型请求、工具调用、状态变化、审批、错误、计量和时间戳。 |
| ToolDefinition | 参数 schema、权限、风险、版本、执行器及健康状态。 |
| Approval | 待审批动作快照、申请人、决策人、决策时间、决策和恢复状态。 |
| MemoryItem | 内容、类型、来源、范围、置信度、创建/过期时间及用户控制状态。 |
| KnowledgeSource | 来源位置、权限范围、索引状态、版本和更新时间。 |
| EvaluationCase | 输入、期望行为、判分规则、版本和运行结果。 |

### 8.1 任务状态建议

queued → planning → running → waiting_for_approval / waiting_for_input → completed / partially_completed / failed / cancelled / budget_exceeded。状态转换应由运行时统一管理，禁止通过非预期跳转掩盖失败。

## 9 验收标准与质量指标

### 9.1 发布验收门槛

- 所有 P0 需求通过对应验收用例。
- 核心使用场景至少完成一次端到端演示，包含成功路径和失败路径。
- 高影响操作审批、取消、拒绝、重试和权限撤销均经过验证。
- 关键运行均可查询完整追踪；日志不包含明文凭证。
- 任务评估集和安全回归集已建立，版本升级有对比结果。
- 文档包含安装、配置、工具授权、运行、恢复和故障排查说明。
### 9.2 建议指标

| 指标 | 定义 / 使用方式 |
| --- | --- |
| 任务完成率 | 满足用户定义验收条件的任务占比；按场景拆分。 |
| 部分完成率与失败率 | 识别不完整交付、工具失败和不可恢复失败。 |
| 工具调用成功率 | 工具参数校验通过且业务操作成功的调用比例。 |
| 审批率与拒绝率 | 用于观察操作风险和用户信任边界。 |
| 来源支持率 | 需要引用的结论中能够映射到有效来源的比例。 |
| 恢复成功率 | 可恢复任务在中断后继续并正确完成的比例。 |
| 单任务成本与耗时 | 按场景观察模型/工具费用和端到端延迟。 |
| 安全拦截有效率 | 越权、注入和高风险未审批测试的阻断结果。 |

## 10 分阶段实施路线

| 阶段 | 建设范围 | 阶段出口 |
| --- | --- | --- |
| 阶段 0 Pi 基线盘点 | 固定 Pi 仓库/版本；运行原生 CLI、SDK、会话、工具、扩展和设置；形成能力差距表。 | 能说明哪些直接复用、包装、扩展或自行实现。 |
| 阶段 1 单 Agent 闭环 | 模型、运行状态、会话、流式交互、工具注册、文件/搜索/命令工具、追踪。 | 研究、文件和代码类基础任务可端到端运行。 |
| 阶段 2 安全和恢复 | 权限、风险分级、审批、取消、幂等、持久状态、长任务恢复和预算。 | 副作用任务具有可验证的控制闭环。 |
| 阶段 3 知识与记忆 | 文件解析、检索、来源引用、上下文管理、用户/项目记忆。 | 回答能够追溯来源，用户可管理记忆。 |
| 阶段 4 评估与工作流 | 任务集、评分、回归、模板、流程分支和后台运行。 | 配置变化可以通过评估发现回归。 |
| 阶段 5 扩展和高级能力 | MCP、插件治理、多 Agent、多模态、Web/API 和连接器。 | 能力按模块加入，权限、日志与评估保持一致。 |

### 10.1 每阶段学习产物

- 架构图和关键数据流。
- 最小可运行示例和对应测试。
- 关键设计取舍及失败案例记录。
- Pi 原生能力与自建能力的边界说明。
- 阶段评估结果和下一阶段技术债清单。
## 11 需求追踪与待决策事项

### 11.1 追踪规则

- 每条需求编号映射到实现模块、任务/Issue、验收用例和版本。
- 变更需求时记录原因、影响模块、风险和优先级调整。
- 每个版本发布前生成 P0/P1/P2 实现状态和未完成项清单。
- Pi 升级时重新核对原生能力、扩展 API 和行为兼容性。
### 11.2 开工前待决策

- 锁定 Pi 的具体仓库、分支、版本与许可要求。
- 确认目标操作系统与执行环境。
- 确定数据默认存储位置、备份方式和删除策略。
- 选择首期模型提供方及是否包含本地模型。
- 确定网页搜索、代码执行和外部连接器的默认权限。
- 决定首期是否要做 Web 界面、知识库和后台任务。
- 制定工具风险等级和需要审批的操作清单。
